# 检测详情：复核草稿与记录变化处理

已纳入本地安装版本 **1.1.9+11**，2026-10-14。76 项主机测试和 2 个 Android 复核场景在版本化源码上复测通过。新证据位于 `C:/Users/29668/LineSight-releases/1.1.9/reports/`；下方开发检查点日志与设备状态为打包前的历史记录。

## 页面行为

- 修改复核依据或结论后显示未提交状态。点击返回会询问是否放弃；取消可继续编辑。
- 输入不满足现有 3–2000 字符限制时，在字段旁显示原因。保存期间禁止再次提交、修改输入或返回。
- 保存成功后显示已保存状态，原始检测判定不变；未修改的已保存复核不会再次提交。
- 未编辑的表单自动刷新到最新记录；有草稿时，记录变化会保留草稿并暂停提交。
- 用户可以放弃草稿、载入最新复核，或核对最新证据后明确选择保留草稿继续复核。确认期间再次变化的记录必须重新核对。
- 记录被移除或归档后，未提交文字仍显示为可选择复制的草稿。未提交草稿会阻止当前页面归档；已归档记录仍可恢复，再重新核对。
- 草稿仅在当前页面内存中存在，未写入数据库。账户锁定或会话重置会清除页面及草稿，离开提示不会阻止锁定。
- 合成工件预览的底部图例在窄屏、大字号下自动换行。保留原文字大小和“示例画面”标识。

## 数据一致性

`ReviewRecordVersion` 对表单读取时的整条检测记录生成不可变快照，包括检测证据、配方快照、复核结果、依据、复核人员、时间及归档状态。模型往返编码统一 UTC 时刻和配方字段次序，避免等价数据因 Map 插入次序不同产生误报。

详情表单提交时携带该快照。`AppStore.review` 在已有原子提交流程中核对当前记录，不匹配则拒绝写入，不追加审计、不改变 revision。其他记录、当前配方或工位名称的更新不使这条记录的草稿失效。相同记录内容被恢复为完全相同的值时仍视作等价快照；它不是单调递增的历史编号。

旧的内部调用可以省略 `expectedVersion`，保持既有直接复核行为。权限、原始判定保留、审计字段、SQLite schema 3、备份及导出格式保持兼容。复核错误仍通过 Future 返回；已移除记录提供明确的中文错误信息。
