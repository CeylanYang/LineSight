# LineSight 页面结构与导航调整方案

本文件记录最初的结构分析与设计方案。用户随后授权实施，实际调整与交付以 [界面与导航调整](UI_DELIVERY_20261024.md) 为准。方向以国内常用 App 的功能宫格、分类导航、状态入口和紧凑列表为参考：常用功能直接可见，内容丰富且分区清楚。

## 1. 已确认的问题

| 现状 | 对操作的影响 | 调整方向 |
| --- | --- | --- |
| 未登录工作台的横幅和提示卡各有一个“登录”，都跳同一登录页，用户还要再按登录 | 重复入口增加一次无意义跳转，刷卡和演示入口首屏不可见 | 工作台未登录状态直接呈现“登录工作区”、登录、刷卡登录、进入演示团队 |
| 工作台大横幅重复展示任务数量；质量概览在手机上以两列三张大卡排成两行 | 少量信息占用两行卡片，推迟常用功能出现 | 页头收紧，三项指标合为横向摘要，注明各自统计范围 |
| 概览后继续堆叠三组折叠待办、七天趋势、五条生产任务，快捷操作才出现 | 常用入口需要长距离滚动，首页承担过多列表和统计职责 | 首屏优先功能宫格；生产独立；完整趋势进入质量报告 |
| 我的待办、底部待办提醒和快捷通知多处重复 | 用户要辨认几个相似入口是否对应不同内容 | 顶部通知统一入口；首页只显示必要的个人待办摘要 |
| 生产任务是工作台中的长区域，主导航却没有生产 | 日常核心对象没有稳定位置 | 主导航增加“生产”，直接进入现有任务列表 |
| 配方中心只是三个跳转菜单，列表仍在下一层 | 分类页变成中转页 | “配置”内用页内分类直接显示打印配置、检查模板列表 |
| 我的混入质量报告等业务功能；我的卡片在账户资料后 | 功能归属与名称不符合寻找习惯 | 业务归业务；卡片在“我的”直接可见，头像进入资料编辑 |
| 任务详情先展示 186 高的大图及较长信息区，再显示操作和页内分类 | 用户进入任务后不能立即判断该做什么 | 先呈现状态、关键字段与主操作；证据进入证据区域；主要分类前移 |
| 报告导出位于长统计页面的底部 | 查看报告和导出需要滚动寻找 | 顶部提供有文字的“导出/报告”操作，保留当前筛选范围 |
| 部分入口仅以图标出现，主要界面还有面向展示的英文眉题 | 核心业务操作需要猜测，装饰占据空间 | 常用操作使用明确中文名称，图标辅助识别 |

代码依据：`lib/screens/cloud_shell.dart`、`lib/cloud_workbench.dart`、`lib/screens/cloud_tasks.dart`、`lib/screens/cloud_profiles.dart`、`lib/screens/cloud_business.dart`。截图依据：`acceptance/native50-batch`、`acceptance/roles78-batch`、`acceptance/secondary66-batch`。旧版截图只用于辅助确认仍存在于当前源码中的结构。

## 2. 参考国内常用 App 的组织方法

这是可迁移的交互模式归纳，不声称已实时逐屏检查这些 App 的最新版本。

- 支付宝：顶部常用工具、功能宫格、明确的业务分区；对应本 App 的在线质检、扫码、新建任务和业务工具入口。
- 淘宝、京东：分类入口、状态分类、可持续浏览的列表；对应生产任务状态、待检列表、检验记录。
- 拼多多：明确的中文动作、可直接点击的状态入口和持续可见的主要操作；对应送检、登记检验、异常处理和提交。
- 闲鱼：明确区分浏览内容、发布动作、消息和个人管理；对应任务、创建、通知和账户管理的职责划分。

借鉴入口组织和展示方法，业务内容继续使用现有任务、检验、配置及团队能力。信息密度通过减少重复横幅、说明和中转页提高；中文标签、可读字号及触摸面积要保留。

## 3. 未登录与登录后的工作台

### 未登录

开屏后，工作台主体直接展示：

```text
LineSight
登录工作区
简短用途说明

[ 登录 ]
[ 刷卡登录 ]
[ 进入演示团队 ]
```

“登录”直接启动现有账号认证流程；“刷卡登录”直接进入扫描状态；演示直接调用现有独立演示登录。账号认证仍复用现有云端认证，不增加自制密码校验。删除工作台上的两个重复登录按钮及“先进入登录说明页再点登录”的路径。

需要登录的深链接或会话失效状态复用同一登录区，记录目标页面。成功后恢复可访问目标；普通首次登录进入工作台；取消时返回来源。工作区数据加载中、未加入团队、加载失败分别显示真实状态，不能伪装为零条任务。

### 登录后

建议布局顺序：

```text
当前团队 ▼                                  通知
搜索任务号、批次或名称

在线质检     扫码追溯     新建任务     质量报告

待检任务     异常处理     检验记录     打印配置
检查模板     团队成员     我的卡片     同步草稿

质量概况
今日待检  —  |  异常处理中  —  |  今日已关闭  —

我的待办                                    查看全部
最多两条直接可处理的事项，附状态和时间

工作台       生产       质检       配置       我的
```

- 顶部四项使用小方块图标和短标签；后两行使用紧凑宫格。标准字号下首屏显示全部常用入口，避免横向滑动寻找第二页。
- 查询复用现有任务搜索，提交后进入带条件的生产列表，不另开发全局搜索服务。
- 快捷入口直接到目标列表、相机、表单或报告，不先进入一张介绍页。扫码页同时提供手动输入，合并查找位置。
- 质量概况合为一块三列摘要；每列可点击到相同统计范围的列表。保持现有统计口径，清楚区分“今日”和全部处理中数据，数据未就绪显示占位而非 0。
- 首页删除生产任务列表和七天趋势长列表。个人待办最多两条，点击直接打开相关任务的处理区域；无待办时使用一行空状态。
- 顶部团队名称可切换工作区；通知统一从右上角进入，未读数以角标展示。
- 不同权限使用稳定布局；只读成员隐藏写操作并使用已有查询入口补位，不改变主导航顺序。页面入口与服务端权限一致。

## 4. 五项主导航及职责

| 主导航 | 直接展示的内容 | 常用操作 |
| --- | --- | --- |
| 工作台 | 功能宫格、简要概况、个人紧急待办 | 在线质检、扫码、新建、报告 |
| 生产 | 生产任务列表 | 搜索、全部/待打印/打印中/待质检/异常/已关闭分类、新建、查看详情 |
| 质检 | 页内“待检 / 检验记录 / 质量报告”分类，直接显示内容 | 登记检验、复检、追溯、按当前范围导出 |
| 配置 | 页内“打印配置 / 检查模板”分类，直接显示列表 | 新建、编辑、复制、带配置创建任务 |
| 我的 | 个人资料、我的卡片、团队成员、账户安全、同步草稿、设置 | 绑定卡片、会话管理、语言、更新、退出 |

“待检”和“异常”复用现有查询、状态和处理路径。相同业务入口共享目标页面及条件，避免主页快捷入口和主导航形成两套数据列表。旧本机工具保留在“我的 → 数据与本机工具”，不占据日常云端配置的主要分类。

## 5. 详情、表单与返回

- 任务详情：首屏显示名称、状态、批次/数量/负责人等关键字段；“概览 / 质检 / 异常 / 历史”前移。图片与次要来源信息放在对应内容区。底部固定当前状态的主要操作，例如开始打印、送检、登记检验或处理异常。
- 从待办进入：直接定位相关检验或异常；“处理异常”直达异常处理表单，多条异常时先列出待选择对象，不只滚动到一个还需再次寻找按钮的区块。
- 检验/异常表单：必要字段先展示，补充说明及照片按业务顺序排列，固定提交区域，键盘不能遮挡；未保存返回使用已有草稿和确认机制。
- 配置和模板详情：主要的“使用此配置/模板创建任务”保持可见；编辑、复制作为次要操作，避免长列表后才出现主要按钮。
- 质量报告：顶部范围筛选和有文字的导出入口，导出选择复用 CSV、预览、系统 PDF；带入当前列表筛选，不跳回全团队默认范围。
- 我的：头像进入资料；我的卡片、团队成员、账户安全均是直接可见的行入口。安全中的修改密码、登录设备等低频项允许保留合理层级。
- 系统返回和左上返回均回到真实来源；保留列表筛选、页内分类和滚动位置。表单成功回到来源的对象/列表并刷新，不把每个操作都送回工作台。
- 切换底部导航属于同级切换，不堆叠新的同级页面。跨区快捷入口选择目标导航和页内分类；详情作为目标区域下的一层页面。
- 鉴权必须发生的位置保留鉴权；减少中转页不改变认证、团队隔离和写操作权限。

## 6. 后续改造顺序与验收

按现有业务重组顺序实施：登录区 → 工作台宫格与概况 → 生产主导航 → 配置/质检直接列表 → 详情及表单主按钮 → 返回路径。

验收只聚焦这次调整：

1. 未登录首屏可见账号、刷卡和演示三种操作，不出现双重登录入口或额外登录中转。
2. 常见手机宽度 360/390/412 逻辑像素、标准字号下，不滚动即可找到顶部四项及常用宫格；大字时允许增加高度并保持可读、可点。
3. 三项质量概况组成横向摘要；主页没有五条生产任务和七天趋势的长列表。
4. 从任一顶层页面切换至生产列表只需点一次底部“生产”；配置页直接显示列表；我的可直接进入卡片管理。
5. 顶部快捷入口一步到目标功能；详情一步到当前主要操作；对象选择、必要认证和提交确认不作为可删掉的中转。
6. 搜索/筛选后进入任务、打开表单并返回，原查询和位置保留；扫码、通知及深链接从各自来源进入正确对象。
7. 无数据、无权限、未加入团队、认证过期和网络错误均有相应状态与可用动作；不通过隐藏错误来获得视觉整洁。
