# 1.1.31 摄像头轮廓与扫码追溯

照片上传和旧照片预览统一采用 mean-shift 平滑、Canny、Zhang-Suen 骨架化。12张内置工件轮廓参考由对应原图重新计算，替换原先重复原图的 edge 素材；本机记录详情加入轮廓参考。用户上传照片始终使用对应照片处理，不套用参考素材。

工作台增加在线质检入口，用户开启摄像头后低分辨率采集，最多一个请求在途，每900毫秒以上发送一帧；服务端完成处理并返回原图、轮廓和计算时长。画面不作为照片证据落库，用户选择“使用当前画面”后才进入现有加密待上传队列。后台、关闭页面及身份／团队切换释放相机或隐藏原结果。

扫码支持任务二维码、批次和工件SN。查询精确匹配且遵守团队权限，读取服务端任务状态；工件SN另显示最新轮次的逐件判定。任务码页面增加批次二维码。生成的演示二维码和Code128条形码对应已存在的独立演示团队数据，打印后可用于后续真机扫码。

## 证据来源

- `live-api.json`、`live-batch.json`、`live-piece.json`：实际HTTPS接口验证，包含工件合格状态、批次已关闭状态、匿名401及跨工作区404。
- `cloud-frame-*-source/processed.png`：由已有参考照片转换BGRA缓冲，经实际云接口处理的结果，非手机拍摄。
- `reference-*.png`：已有参考原图与本机运行同一生产算法的结果。
- `*-generated.png`：生成的可打印追溯码，非Android截图。
- `png/*desktop-render.png`：Flutter桌面组件渲染，使用实际算法输出与云端响应对应的演示夹具，中英文各两张，非Android截图。

新后端迁移0007前自动备份，28张原表全部旧行保留且外键、健康检查通过。完整测试和安装包结果见validation.json。未启动虚拟机、模拟器或QEMU，未安装、卸载或清除手机数据。物理摄像头、实际扫码与NFC卡片尚未进行真机验证；NFC本批仅加入依赖，登录绑定继续开发。
