# LineSight 1.1.37+8061

本批完善统一登录与会话失效后的页面恢复。登录页对个人与团队共用，不要求用户填写端点，保留账号、NFC和独立演示团队入口。

## 操作变化

- 检验、异常处理、新建任务页面会话失效后，可从二级登录回到原草稿。重新核验同一账户、原工作区和当前权限。
- 检验恢复时重新读取最新任务。版本变化转入冲突对比，不直接采用旧结论。
- 登录成功后恢复页面，不自动重发提交。原备注、数量、检查项、附件关联和请求键保留。
- 取消登录或登录后工作区加载失败时，不离开当前流程。读取失败提供重试。
- 换账户或降为只读后，原可写表单不恢复，也不展示旧草稿。只读成员仍可恢复查看有权访问的任务详情。
- 恢复后的表单手动提交完成，返回父任务详情会重新读取状态，随后可返回原入口。

## 验证

211 项 Flutter 测试通过，静态分析无问题。新增 12 项回归覆盖上述恢复路径。后端代码未改，本批未重跑既有 57 项后端测试。

普通 Android release APK 覆盖原 8060 安装为 8061，安装前后持久化文件、数据库、密钥别名和校验标记一致，详见存储 JSON。没有卸载主 App、清空 App 数据或向手机安装。

实际云端会话验证只撤销本轮新建的 Android 演示会话。脚本通过前后会话差集确定唯一目标，其他会话不撤销。旧会话提交被拒后，在 App 内重新登录恢复原备注。独立 HTTPS 查询确认登录后任务尚未提交，再由用户点击提交，最终只产生一条检验记录。该过程操作独立演示工作区中的本批新任务，不修改既有任务。

`live-reauthentication.json` 保存任务状态和验证标记，`native-journey.json` 保存普通 APK 的页面观察与 PNG 哈希。会话标识与登录令牌不进入公开材料。

初次 APK 验证发现追溯入口在重新登录后重建父页，提交返回后保留旧状态。已补充追溯入口回归，任务详情重新成为当前页面时重新读取。`first-attempt-cloud.json` 保留初次云端验证和父页失败标记，最终 PNG 与主验证文件来自修复后的重新验证。最终安装包再次覆盖安装也进行存储对比。

## 安装与素材

- `LineSight-1.1.37-8061-preview.apk` 沿用现有预览签名，供同签名旧版覆盖升级。
- `LineSight-1.1.37-8061-production.apk` 使用正式签名，供同正式签名安装链使用。现有预览签名不能直接覆盖为正式签名。
- 两包均为非调试构建，支持 ARM64 与 x86_64，不含验收插件和存储检查工具。
- `107-unified-login-*-desktop-render.png` 为中英文 Flutter 组件渲染。
- 文件名以 `-emulator.png` 结尾的是普通 Android release APK 模拟器原始截图，分别记录草稿、失效登录、统一登录、恢复后草稿、手动提交后的父任务详情及返回入口。
- 全部历史 PNG 保持不变。完整素材索引为 `../DEMO_INDEX.html`。

完成后模拟器恢复原 1080×1920 覆盖分辨率、420 密度并关闭。物理 NFC、多卡型、双真机及 10 位外部用户仍待验收。SMTP 找回邮件与异地备份/恢复等计划项继续，完整产品计划尚未宣告完成。
