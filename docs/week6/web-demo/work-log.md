# 网页制作工作记录

## 需求与设计

- 阅读用户提供的 `appdist.zip`：独立 HTML/CSS/JS、桌面品牌介绍、手机容器、底部导航与二级详情。
- 对照现有 Flutter 页面、品牌标志和 Week 6 Android 截图，确认工作台、检测记录、配方中心、我的四个主导航。
- 用户确认中英切换，以及参考包的手机展示形式。
- 确定直接进入准备好的工作台，采用客户语言；页面只提供浏览与视图交互。

## 实现

- 新增独立 `live-demo/`，不依赖 Flutter Web、Django 或第三方前端框架。
- 统一生产任务、工位、配方、质检记录和成员的数据引用；用同一内容驱动列表、详情和首页数字。
- 制作蓝绿浅色页面、浅色手机外框和品牌背景，以及三组零件图像和对应蓝色轮廓 SVG。
- 完成任务到质检、图片到记录、异常到负责人、配方到工位和团队到任务的跳转。
- 加入完整语言切换、浏览器历史、列表滚动位置恢复、直接详情入口的返回路径与未知路由回到工作台。
- 图片放大支持关闭按钮、Escape、键盘焦点约束和背景不可交互。
- 提供无依赖构建脚本、本地预览、部署配置和带 SHA-256 的构建清单。

## 自测与调整

- 首轮覆盖 37 个页面状态的中英文检查：没有脚本错误和横向溢出；发现英文「我的」页语言提示含中文，已改为完整英文提示。
- 调整程序焦点样式，保留交互控件的键盘焦点，同时移除页面标题的多余边框。
- 提高正文、状态和列表文字尺寸；截图使用浏览器减少动态效果偏好，避免捕获过渡动画。
- 完整截图复查发现零件图像的网格布局高度溢出和数量图表的基线偏移；已约束图像尺寸、调整图像视口并统一柱形图基线，新增图像裁切检查。
- 完整验收脚本与实际结果见 `validation-results.json`；最终截图在 `screenshots/`。
- 最终版本通过 83 个页面状态、17 组场景和 6,126 项断言；保存 19 张原始页面截图。浏览器错误、失败响应与远端请求均为 0。
